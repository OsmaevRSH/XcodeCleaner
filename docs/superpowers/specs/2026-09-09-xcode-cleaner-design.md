# XcodeCleaner — дизайн

Дата: 2026-09-09

Документ описывает то, что делает код на момент последней правки. Если поведение
разошлось с текстом, правится текст.

## Цель

macOS-приложение с UI, заменяющее скрипт `~/Desktop/Xcode Cleanup.command`.
Чистит регенерируемые данные Xcode и симуляторов, старые Archives, неиспользуемые
Xcode.app и toolchains, проектные кэши, а также размонтирует маунты Arcadia и
удаляет их store.

Целевая машина: macOS 26, Xcode 26.2, Swift 6.2, arc в `PATH`.

## Сборка

SwiftPM-пакет без Xcode-проекта.

- `Package.swift`: библиотека `XcodeCleanerCore` (вся логика, никакого SwiftUI),
  executable `XcodeCleaner` (UI, macOS 15+), test targets `XcodeCleanerCoreTests`
  и `XcodeCleanerTests`.
- `build.sh`: `swift build -c release`, сборка `XcodeCleaner.app`
  (`Contents/MacOS/XcodeCleaner`, `Contents/Info.plist`, `Contents/Resources/AppIcon.icns`
  из `Assets/AppIcon.png` через `iconutil`), ad-hoc подпись `codesign -s -`,
  копирование `.app` в `~/Desktop`.
- App Sandbox не используется: нужен доступ к `~/Library`, `/Applications`,
  запуск `xcrun`, `arc`, `df`.
- Исходник: `~/Developer/XcodeCleaner`, git-репозиторий.

## Структура UI

Одно окно, `NavigationSplitView`, боковая панель с тремя разделами.

### Шапка (общая для всех разделов)

Полоса заполнения диска и подпись «Свободно X из Y». Справа «Освободится» —
сумма размеров отмеченного в текущем разделе, появляется только когда что-то
выбрано. После очистки на её месте «Освободилось» — фактическая разница двух
замеров диска, показывается до следующего изменения выбора. Разница может выйти
отрицательной, если во время очистки писали другие процессы; такое значение
показывается как ноль.

### Раздел «Xcode»

Одна строка списка — одна категория, а не путь к папке: чекбокс, заголовок,
одна строка про последствия и размер. Стрелка раскрывает конкретные элементы
внутри категории с отдельными чекбоксами; по умолчанию категория свёрнута.
Клик в любом месте строки — хоть категории, хоть элемента внутри неё — ставит
её галочку, а стрелка только раскрывает и сворачивает.

Чекбокс категории трёхпозиционный: `square` — не выбрано ничего,
`checkmark.square.fill` — выбрано всё, `minus.square.fill` — выбрана часть.
Клик выбирает категорию целиком, а если она уже выбрана целиком — снимает
выбор. Частичный выбор обязан быть видимым: невыбранная на вид категория, из
которой удаляются четыре элемента из пяти, — это ложь в интерфейсе.

Категории разбиты на две группы `CleanupGroup`: `.safe` («Восстановится само»)
и `.attention` («Не восстановится автоматически»).

Сканирование двухфазное. `Scanner.scan()` строит структуру, не обходя ни одного
дерева, — список появляется сразу. Во второй фазе сначала работает
`Scanner.discoverProjectCaches(for:onDiscover:)` — ограниченный по глубине обход,
который находит папки `.build`, — а затем `Scanner.measureSizes(for:onSize:)`
считает размеры не более чем четырьмя параллельными обходами и отдаёт каждый
результат по мере готовности; `AppModel` копит их и применяет пачками (каждые
150 мс или каждые четыре размера), до готовности в строке стоит индикатор.
Поиск и подсчёт идут последовательно: ограничение «не больше четырёх обходов
одновременно» живёт в `measureSizes`, и обход поиска рядом с ним был бы пятым.

При первом сканировании сессии предвыбираются категории группы `.safe`, кроме
`.projectCaches`: она тоже восстановится сама, но только полным резолвом Tuist и
SwiftPM в каждом маунте, по сети. Приложение не должно открываться уже
взведённым на такое. Последующие сканирования выбор не трогают.

| Категория (`CleanupKind`) | Пути / источник | Группа |
|---|---|---|
| `xcodeCaches` — «Кэши сборки» | `~/Library/Developer/Xcode/DerivedData`, `~/Library/Caches/com.apple.dt.Xcode` | `.safe` |
| `previews` — «Превью и документация» | `~/Library/Developer/Xcode/UserData/Previews`, `.../DocumentationCache` | `.safe` |
| `deviceSupport` — «DeviceSupport» | `~/Library/Developer/Xcode/{iOS,watchOS,tvOS,visionOS} DeviceSupport` | `.safe` |
| `simulatorCaches` — «CoreSimulator и SwiftPM» | `~/Library/Developer/CoreSimulator/Caches`, `~/Library/Caches/com.apple.CoreSimulator`, `~/Library/Caches/org.swift.swiftpm`, `~/Library/Logs/CoreSimulator` | `.safe` |
| `simulators` — «Симуляторы» | `xcrun simctl`, режим-переключатель: только недоступные / стереть все / удалить все / удалить все + runtimes | `.safe`, но `isDestructive` несёт сам элемент по выбранному режиму |
| `archives` — «Archives старше N дней» | `~/Library/Developer/Xcode/Archives/**/*.xcarchive`, степпер N (0…365, шаг 5, по умолчанию 30), список конкретных архивов | `.attention` |
| `xcodeApps` — «Старые Xcode» | `/Applications/Xcode*.app` кроме результата `xcode-select -p`; каждый отдельным чекбоксом | `.attention` |
| `toolchains` — «Toolchains» | `~/Library/Developer/Toolchains/*.xctoolchain` кроме симлинка `swift-latest` и его цели; каждый отдельным чекбоксом | `.attention` |
| `projectCaches` — «Проектные кэши» | `~/.cache/tuist`; для каждого маунта Arcadia со статусом `mounted` и каждого корня проектов: `<корень>/Derived`, `<корень>/DerivedData` плюс найденные обходом папки `.build`; найденные обходом папки `.build` в каждой папке из `projectSearchFolders` | `.safe` |

Где искать, задают два независимых списка. Корни проектов внутри маунтов
задаёт `CachePaths.projectSearchRoots` — пути от корня маунта, по умолчанию
`mobile/saft/ios` и `mobile/music/ios` (`CachePaths.defaultProjectSearchRoots`).
Папки, которые обходятся напрямую, а не в каждом маунте, задаёт
`CachePaths.projectSearchFolders: [URL]` — абсолютные пути, по умолчанию пусто: обходить папку, которую пользователь не выбирал, не
то, что чистильщик решает сам. `AppModel` читает оба списка из `UserDefaults` по
ключам `ProjectSearchRoots` и `ProjectSearchFolders` и передаёт значением в
`CachePaths.init`; ядро в `UserDefaults` не ходит. Меняются они в окне, через
лист «Настройки»; `defaults write` остаётся скриптовым эквивалентом тех же
ключей.

`Derived` и `DerivedData` — выходы Tuist на известном месте, они предлагаются по
фиксированному пути, потому что могут появиться между сканированием и очисткой.
Папки `.build` фиксированным списком не описываются: `swift build` оставляет по
одной рядом с каждым `Package.swift`. Их ищет обход, и потому не в `scan()`, а
во второй фазе, рядом с подсчётом размеров: холодное чтение одного корня в
FUSE-маунте стоит секунд. Точек входа две, обход у них общий:

- `ProjectCacheScanner.discoverBuildDirectories(mounts:cachePaths:maxDepth:timeBudget:now:deviceID:fileManager:)`
  — корни `projectSearchRoots` в каждом маунте со статусом `mounted` (у
  размонтированного за папкой ничего нет, а его байты лежат в store и уже учтены
  вкладкой Arcadia). Заголовок строки — `<имя маунта> · <путь от корня маунта>`.
- `ProjectCacheScanner.discoverBuildDirectories(inFolders:home:maxDepth:timeBudget:now:deviceID:fileManager:)`
  — папки `projectSearchFolders`. От маунтов и `arc` не зависит: так приложение
  работает и без Arcadia. Заголовок строки — путь с домашней папкой,
  сокращённой до `~` (`CachePaths.displayPath`), подзаголовок — полный путь.
  Папка, которая сама проходит через симлинк, не обходится: найденное под ней
  было бы записано через симлинк и отклонено allowlist-ом удаления.

Обе возвращают `ProjectCacheScanner.Discovery`: найденные каталоги,
отсортированные по пути, и предупреждения. Обход ограничен со всех сторон:
глубина не больше `maxDepth` (`defaultMaxDepth`, 8); симлинки не раскрываются;
найденная `.build` — результат, внутрь неё обход не идёт; каталоги `.git`,
`.arc`, `.swiftpm`, `.overlay_v2`, `node_modules`, `DerivedData`, `Derived`,
`xcuserdata`, бандлы с суффиксами `.xcodeproj`, `.xcworkspace`, `.framework`,
`.app`, а также `~/Library` и `~/.Trash` (только непосредственно в домашней
папке) пропускаются целиком; обход прерывается по `Task.isCancelled`.

Два правила безопасности действуют в обоих случаях, в том числе в маунтах:

- `.build` засчитывается, только если в том же каталоге лежит обычный файл
  `Package.swift` — не каталог и не симлинк с таким именем. В произвольной папке
  `.build` может принадлежать чему угодно, а очистка удаляет её содержимое.
  `.build` без манифеста не засчитывается и не обходится.
- Обход не переходит границу файловой системы. Устройство корня (`st_dev` через
  `lstat`, `ProjectCacheScanner.deviceID(of:)` — то же число, что `SafeDeleter`
  читает как `.systemNumber`) запоминается, и каталог на другом устройстве не
  обходится и не засчитывается. Так обход из `~` не заходит в FUSE-маунты
  Arcadia, на сетевые и внешние диски; корень на внешнем диске обходится
  целиком, потому что граница считается от него. Корень без устройства (его нет
  или его не прочитать) не обходится. Поиск устройства передаётся параметром
  `deviceID`: во временных каталогах тестов устройство одно.

На каждый корень и каждую папку отводится `timeBudget` (`defaultTimeBudget`,
30 с) по часам `now`. Когда время вышло, обход этого корня останавливается,
найденное к этому моменту остаётся, а в `Discovery.warnings` появляется
«Поиск в <путь с ~> остановлен через 30 с — укажите папку точнее»; остальные
корни обходятся дальше. Часы и бюджет — параметры, чтобы тест мог остановить
корень, не ожидая 30 секунд; `Scanner` принимает бюджет в `init`
(`discoveryTimeBudget`).

`Scanner.discoverProjectCaches(for:onDiscover:onWarning:)` обходит сначала
маунты, по одному, затем папки, по одной, каждый обход в дочерней задаче, и
отдаёт найденное по одному элементу. Элемент, уже бывший в
`result.projectCacheItems` или уже отданный из другого корня (папка внутри
маунта, вложенные папки), повторно не отдаётся; первым идёт маунт, поэтому
`.build` в маунте сохраняет его имя. Предупреждения о бюджете уходят в
`onWarning`. `AppModel` дописывает элементы в `scan.projectCacheItems`, а
предупреждения — в журнал (и то и другое со сверкой поколения
`measureGeneration`), и только потом считает размеры. Пока поиск идёт, у
категории горит индикатор незавершённости. Allowlist удаления выводится из
`result.projectCacheItems`, поэтому дописанный элемент — из маунта или из
папки — становится удаляемым сам, без отдельного списка; фиксированные подпапки
добавляются в allowlist сверх этого.

Путь, который сам является симлинком или лежит за симлинком, в список не
попадает; вместо него в журнал уходит предупреждение. Это касается и папок
поиска. Папка поиска, которой нет на диске, из настроек не удаляется: `scan()`
пишет в журнал «Папка для поиска не найдена, пропущена: <путь с ~>», и обход
её пропускает.

Список категорий пересобирается только при изменении результата сканирования,
режима симуляторов или возраста архивов: SwiftUI спрашивает его десятки раз за
проход отрисовки, а сборка списка стоит фильтра архивов и интерполяции строк на
элемент.

### Раздел «Arcadia»

Список из `arc mount --list --json` с шапкой и колонкой-чекбоксом: имя маунта,
статус (`mounted`/`unmounted`), дата последнего использования, размер store.
Клик в любом месте строки ставит её галочку; ради этого раздел и сделан списком,
а не `Table`, который ловит клик только внутри клетки и оставляет мёртвые полосы
между колонками. Основной маунт `~/arcadia` показывается с замком и без
чекбокса, и его строка ни на что не отвечает. Пока идёт сканирование, поверх
списка тот же индикатор «Сканирование…», что и в разделе Xcode.

Дата последнего использования — `modificationDate` папки `<store>/.arc`, с
откатом на сам store. Она отражает реальную работу с веткой, тогда как mtime
корня store не меняется после создания.

Создание маунтов в приложении не поддерживается: это чистильщик.

Действий два.

**«Размонтировать выбранные»** — `arc unmount <path>` для каждого выбранного
смонтированного маунта. Store остаётся на месте. Если `arc` отказал, под
таблицей появляется полоса с предложением повторить с `--force`; предложение
живёт, пока маунт всё ещё смонтирован, и снимается при смене раздела.

Перед любым размонтированием измерение размеров останавливается. Обход внутри
живого FUSE-маунта — ровно то, из-за чего том оказывается busy: приложение не
должно ломать собственное размонтирование, а потом предлагать `--force` для
тома, который читает само.

**«Удалить N маунтов · размер»** — снимает всё, что связано с маунтом:

- если маунт смонтирован, `arc unmount <path>`; ответ «Repository seems to be
  already unmounted» не считается ошибкой, потому что список арк может быть
  устаревшим;
- `arc unmount --forget <path>`; его неудача не прерывает операцию;
- если store всё ещё существует, он удаляется напрямую через `removeItem`, но
  только внутри `<home>/.arc/stores/`; Корзина в этом пути не участвует;
- пустая папка маунта снимается через `rmdir(2)`.

Операция считается неуспешной, только если и `--forget` не сработал, и store
удалить не удалось. Размер store берётся из уже измеренного: деструктивный путь
не обходит гигабайты ради числа, которое UI уже показал.

Обе операции идут по списку целиком: отказ на одном маунте не отменяет
остальные, а все сообщения об ошибках показываются вместе.

Все `arc`-команды запускаются с рабочей директорией `~`.

### Раздел «Журнал»

Живой построчный вывод всех команд и итог. Каждая строка получает собственный
идентификатор: текст строк повторяется, а нумерация по индексу заставляла бы
пересобирать массив на каждую строку. Буфер в памяти ограничен 5000 строк и
подрезается блоками по 1000; полный лог всё равно пишется в файл
`~/Desktop/Xcode Cleanup Logs/cleanup-<дата>.log`.

Автопрокрутка работает, только когда вид уже внизу. Если пользователь
прокрутил вверх, вывод больше не тянет вид за собой, а в углу появляется кнопка
«К последним строкам».

### Подтверждение

Кнопка внизу окна действует только на текущий раздел: на вкладке Xcode она
чистит категории Xcode, на вкладке Arcadia удаляет отмеченные маунты. Она
открывает модальный лист: список пунктов с размерами и суммарный размер.

Если в списке есть `simulators` или `simulatorCaches`, отдельной строкой
сказано, что запущенные симуляторы будут выключены: `Cleaner.run` делает
`simctl shutdown all` до того, как трогать хранилища симуляторов.

Для деструктивных пунктов есть чекбокс-подтверждение, и его текст зависит от
операции, потому что удаление в этих двух потоках означает разное:

- очистка Xcode — «Понимаю, что отмеченные данные уйдут в Корзину и сами не
  вернутся»: `SafeDeleter.trash` кладёт `.xcarchive`, `Xcode.app` и toolchains в
  Корзину, откуда их можно достать;
- удаление маунтов — «Понимаю, что store будут удалены навсегда, мимо Корзины»:
  `removeItem` Корзину не использует.

Без чекбокса кнопка «Удалить» заблокирована. Return принадлежит кнопке
«Отмена», Escape тоже отменяет: лист открывается с готовой деструктивной
кнопкой, и случайный Return не должен ничего удалять. Кодовые фразы из скрипта
не используются.

### Настройки

Кнопка-шестерёнка в левом углу нижней полосы, перед «Пересканировать», с
подсказкой и accessibility-подписью «Настройки». Отдельного раздела в боковой
панели у настроек нет: настройки не просматривают, их открывают и закрывают.
Кнопка заблокирована на тех же условиях, что и «Пересканировать»: сохранение
запускает сканирование, а `rescan()` во время другого сканирования отказывает,
и настройки оказались бы применены при старом списке на экране.

Лист `SettingsSheet` — заголовок «Где искать проектные кэши» и два раздела с
заголовками. Ширина листа прежняя, 520 точек; по высоте он растёт по
содержимому.

Раздел «В маунтах Arcadia»: справа от заголовка кнопка «Сбросить», под ним абзац
о том, что приложение ищет `.build`, `Derived` и `DerivedData` внутри этих папок
каждого смонтированного маунта и что пути задаются от корня маунта, и
`TextEditor` моноширинным шрифтом: один корень в строке, список короткий и его
обычно вставляют целиком. Под полем — сколько корней получилось, а отброшенные
строки перечислены красным вместе с причиной.

Раздел «Другие папки»: справа от заголовка кнопка «Добавить папку…», под ним
список выбранных папок в рамке, как у поля выше, — по строке на папку, путь с
`~` моноширинным шрифтом (полный путь во всплывающей подсказке) и кнопка
`minus.circle` с accessibility-подписью и подсказкой «Убрать папку». Пустой
список читается как «Папки не выбраны». Под списком строка `.secondary`:
«Приложение ищет папки .build рядом с Package.swift на глубину до восьми
уровней и не заходит на другие диски и в маунты Arcadia.» Руками пути в этот
список не вводятся: «Добавить папку…» открывает `NSOpenPanel` — только
каталоги, выбор нескольких, кнопка «Добавить». Выбранное проходит через
`normalizedSearchFolders` вместе с уже добавленным, так что повтор остаётся
один раз, а отклонённое (весь диск, системные папки) не добавляется и
показывается красным с причиной до следующего выбора.

Разбор ввода — `CachePaths.normalizedSearchRoots(_:)`, одна реализация на лист
и на чтение `UserDefaults`. Строка обрезается по краям от пробелов и слэшей;
пустая строка молча пропускается, потому что так заканчивается набранный
руками список; строка, в которой после обрезки ничего не осталось, отклоняется
с причиной «пустая строка»; строка с компонентой `..` — с причиной «путь наружу
из маунта»; порядок сохраняется, повтор остаётся один раз.

Разбор папок — `CachePaths.normalizedSearchFolders(_:home:)` рядом с ним, того
же вида: сохранённые папки и отклонённые строки с причинами. Строка обрезается
по краям от пробелов; пустая пропускается молча; `~` и `~/…` раскрываются от
`home`; путь, который и после этого не начинается с `/`, отклоняется с
причиной «нужен полный путь» (сюда же попадает `~другой/…`); затем путь
стандартизуется (`.` и `..` раскрыты, хвостовые слэши сняты), и `/`
отклоняется с причиной «это весь диск», а `/System`, `/Library`,
`/Applications`, `/usr`, `/private`, `/bin`, `/sbin`, `/opt` — с причиной
«системная папка» (сравнение без учёта регистра, как у файловой системы;
папки внутри них разрешены). Существование папки не проверяется: папка на
отключённом диске — всё равно настройка пользователя. Порядок сохраняется,
повтор остаётся один раз.

Кнопок в нижней строке две. «Отмена» — escape-действие, Escape отменяет тоже.
«Сохранить» отдаёт `AppModel.applySearchSettings(roots:folders:)` набранные
корни и выбранные папки.

Хранит их `AppModel.storeSearchSettings(roots:folders:in:)`: оба списка
нормализуются и пишутся под своими ключами, а пустой список удаляет ключ, а не
записывается пустым, чтобы `defaults read` не показывал список, по которому
никто не ищет. Пустой список корней означает встроенные корни, пустой список
папок — отсутствие папок.

Сохранение действует сразу, без перезапуска. `cachePaths`, `Scanner` и
`ArcMountManager` собраны из настроек поиска, поэтому все три пересобираются;
`cancelMeasuring()` вызывается до этого и поднимает `measureGeneration`, чтобы
обход, идущий по старым настройкам, не дописал найденное в новое сканирование.
Следом идёт `rescan()`.

## Архитектура

Вся логика — в `XcodeCleanerCore`, без SwiftUI и без main actor; UI-таргет
`XcodeCleaner` состоит из `AppModel` и представлений.

- `CleanupKind` (enum): категория. Заголовок, строка последствий, группа,
  порядок выполнения (`executionOrder`).
- `CleanupGroup` (enum): `.safe` / `.attention` — восстановится само или нет.
- `CleanupItem` (struct): конкретный путь или simctl-операция, категория,
  размер (nil, пока не измерен), `isDestructive` и `action`
  (`clearContents` / `trash` / `simulators`).
- `ItemResult` и `CleanupReport` (structs): исход по каждому пункту и итог
  прогона с замерами диска до и после; статуса выполнения на самом
  `CleanupItem` нет.
- `CachePaths` (struct): все пути-источники в одном месте.
- `DiskSpace` (struct): свободно/занято/всего, читается из `URLResourceValues`.
- `Scanner` (Sendable struct): только чтение. Строит `ScanResult` из allowlist
  путей, `xcrun simctl list -j`, `xcrun simctl runtime list -j`,
  `xcode-select -p`, `arc mount --list --json`; размеры считает отдельным
  вызовом `measureSizes(for:onSize:)` не более чем в четыре потока.
- `DirectorySizer` (enum): обход дерева с проверкой `Task.isCancelled` каждые
  256 файлов, чтобы отмена доходила до обхода внутри FUSE-маунта.
- `SafeDeleter` (Sendable struct): единственное место удаления. Путь должен быть
  в allowlist, не быть симлинком и не лежать за ним; содержимое каталога
  удаляется по элементам; элемент на другом `st_dev` пропускается с ошибкой.
  Archives, Xcode.app и toolchains уходят в Корзину через
  `FileManager.trashItem`, кэши удаляются напрямую.
- `Cleaner` (Sendable struct): порядок выполнения, `simctl`, отчёт.
- `ArcMountManager` (Sendable struct без состояния): list/unmount/forget/rmdir(2)
  через `CommandRunner`; размеры store считаются вместе с остальными в
  `Scanner.measureSizes(for:onSize:)`.
- `CommandRunner` (protocol + `ProcessCommandRunner`): запуск `Process`,
  построчный стриминг stdout/stderr в лог через `@Sendable` callback.
- `CleanupLogFile` (final class): файл лога, запись под замком прямо из
  фоновых потоков.
- `RussianPlural` (enum): формы числительных для UI и для подписей, которые
  строит сам core.
- `AppModel` (`@Observable`, `@MainActor`): состояние UI, выбор, диск,
  прогресс, журнал.

Порядок выполнения очистки: проверка, что `Xcode`, `Simulator`, `xcodebuild`,
`xctest` не запущены (`pgrep -x`), иначе остановка с сообщением;
`simctl shutdown all`, если в прогоне есть симуляторы или их кэши; кэши;
`simctl delete unavailable`; `simctl runtime dyld_shared_cache remove --all`;
выбранный режим симуляторов; Archives; Xcode.app; toolchains; проектные кэши;
`sync`; замер диска. Ошибка одного пункта не останавливает прогон.

## Тесты

XCTest, основной target `XcodeCleanerCoreTests`:

- Парсинг фикстур JSON `simctl list`, `simctl runtime list`, `arc mount --list`.
- `SafeDeleter` и `Cleaner` во временной папке: удаляют содержимое
  allowlist-каталога, не удаляют сам каталог, пропускают симлинки, отказывают
  пути вне allowlist.
- Фильтр Archives по возрасту.
- Выбор «старых» Xcode и toolchains по активному `xcode-select` и `swift-latest`.
- Формат размеров и формы русских числительных.
- `CommandRunner` подменяется фейком; реальные `arc`/`simctl` в тестах не
  вызываются.
- Разбор корней поиска: обрезка, пропуск пустых строк, отказ пути с `..`,
  порядок и дедупликация.
- Разбор папок поиска: раскрытие `~`, хвостовые слэши, дедупликация, порядок,
  отказ `/`, каждой системной папки и относительного пути с причиной.
- Обход `.build`: манифест рядом обязателен (и в маунтах, и в папках); граница
  устройства — через подменённый `deviceID`; поиск в папках без маунтов;
  пропуск `~/Library` и `~/.Trash`; заголовки с `~`; остановка корня по
  бюджету через подменённые часы, без ожидания 30 секунд; allowlist удаления
  для `.build`, найденной в папке.

Target `XcodeCleanerTests` покрывает из UI только настройки:
`AppModel.cachePaths(defaults:)` на заполненном, пустом, отсутствующем и
целиком негодном значении обоих ключей и `AppModel.storeSearchSettings`. Тест работает в собственном
`UserDefaults(suiteName:)` и удаляет его за собой; домен приложения в тестах не
пишется никогда.

Ручная проверка: `./build.sh`, запуск `.app`, скан, удаление одного тестового
unmounted-маунта, сверка «Освободится» с фактическим df.
