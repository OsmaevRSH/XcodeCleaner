# XcodeCleaner — дизайн

Дата: 2026-09-09

Документ описывает то, что делает код на момент последней правки. Если поведение
разошлось с текстом, правится текст.

## Цель

macOS-приложение с UI, заменяющее скрипт `~/Desktop/Xcode Cleanup.command`.
Чистит регенерируемые данные Xcode и симуляторов, старые Archives, неиспользуемые
Xcode.app и toolchains, проектные кэши, а также размонтирует маунты Arcadia и
удаляет их store.

Целевая машина: macOS 26, Xcode 26.2, Swift 6.2, arc в `PATH`.

## Сборка

SwiftPM-пакет без Xcode-проекта.

- `Package.swift`: библиотека `XcodeCleanerCore` (вся логика, никакого SwiftUI),
  executable `XcodeCleaner` (UI, macOS 15+), test target `XcodeCleanerCoreTests`.
- `build.sh`: `swift build -c release`, сборка `XcodeCleaner.app`
  (`Contents/MacOS/XcodeCleaner`, `Contents/Info.plist`, `Contents/Resources/AppIcon.icns`
  из `Assets/AppIcon.png` через `iconutil`), ad-hoc подпись `codesign -s -`,
  копирование `.app` в `~/Desktop`.
- App Sandbox не используется: нужен доступ к `~/Library`, `/Applications`,
  запуск `xcrun`, `arc`, `df`.
- Исходник: `~/Developer/XcodeCleaner`, git-репозиторий.

## Структура UI

Одно окно, `NavigationSplitView`, боковая панель с тремя разделами.

### Шапка (общая для всех разделов)

Полоса заполнения диска и подпись «Свободно X из Y». Справа «Освободится» —
сумма размеров отмеченного в текущем разделе, появляется только когда что-то
выбрано. После очистки на её месте «Освободилось» — фактическая разница двух
замеров диска, показывается до следующего изменения выбора. Разница может выйти
отрицательной, если во время очистки писали другие процессы; такое значение
показывается как ноль.

### Раздел «Xcode»

Одна строка списка — одна категория, а не путь к папке: чекбокс, заголовок,
одна строка про последствия и размер. Стрелка раскрывает конкретные элементы
внутри категории с отдельными чекбоксами; по умолчанию категория свёрнута.

Чекбокс категории трёхпозиционный: `square` — не выбрано ничего,
`checkmark.square.fill` — выбрано всё, `minus.square.fill` — выбрана часть.
Клик выбирает категорию целиком, а если она уже выбрана целиком — снимает
выбор. Частичный выбор обязан быть видимым: невыбранная на вид категория, из
которой удаляются четыре элемента из пяти, — это ложь в интерфейсе.

Категории разбиты на две группы `CleanupGroup`: `.safe` («Восстановится само»)
и `.attention` («Не восстановится автоматически»).

Сканирование двухфазное. `Scanner.scan()` строит структуру, не обходя ни одного
дерева, — список появляется сразу. Затем `Scanner.measureSizes(for:onSize:)`
считает размеры не более чем четырьмя параллельными обходами и отдаёт каждый
результат по мере готовности; `AppModel` копит их и применяет пачками (каждые
150 мс или каждые четыре размера), до готовности в строке стоит индикатор.

При первом сканировании сессии предвыбираются категории группы `.safe`, кроме
`.projectCaches`: она тоже восстановится сама, но только полным резолвом Tuist и
SwiftPM в каждом маунте, по сети. Приложение не должно открываться уже
взведённым на такое. Последующие сканирования выбор не трогают.

| Категория (`CleanupKind`) | Пути / источник | Группа |
|---|---|---|
| `xcodeCaches` — «Кэши сборки» | `~/Library/Developer/Xcode/DerivedData`, `~/Library/Caches/com.apple.dt.Xcode` | `.safe` |
| `previews` — «Превью и документация» | `~/Library/Developer/Xcode/UserData/Previews`, `.../DocumentationCache` | `.safe` |
| `deviceSupport` — «DeviceSupport» | `~/Library/Developer/Xcode/{iOS,watchOS,tvOS,visionOS} DeviceSupport` | `.safe` |
| `simulatorCaches` — «CoreSimulator и SwiftPM» | `~/Library/Developer/CoreSimulator/Caches`, `~/Library/Caches/com.apple.CoreSimulator`, `~/Library/Caches/org.swift.swiftpm`, `~/Library/Logs/CoreSimulator` | `.safe` |
| `simulators` — «Симуляторы» | `xcrun simctl`, режим-переключатель: только недоступные / стереть все / удалить все / удалить все + runtimes | `.safe`, но `isDestructive` несёт сам элемент по выбранному режиму |
| `archives` — «Archives старше N дней» | `~/Library/Developer/Xcode/Archives/**/*.xcarchive`, степпер N (0…365, шаг 5, по умолчанию 30), список конкретных архивов | `.attention` |
| `xcodeApps` — «Старые Xcode» | `/Applications/Xcode*.app` кроме результата `xcode-select -p`; каждый отдельным чекбоксом | `.attention` |
| `toolchains` — «Toolchains» | `~/Library/Developer/Toolchains/*.xctoolchain` кроме симлинка `swift-latest` и его цели; каждый отдельным чекбоксом | `.attention` |
| `projectCaches` — «Проектные кэши» | `~/.cache/tuist`; для каждого маунта Arcadia со статусом `mounted`: `mobile/saft/ios/Tuist/.build`, `mobile/saft/ios/Derived`, `mobile/saft/ios/DerivedData` | `.safe` |

Проектные кэши ищутся только проверкой существования фиксированных путей.
Рекурсивный обход FUSE-маунтов запрещён; размер проектных кэшей внутри
маунта считается обходом только этих подпапок.

Путь, который сам является симлинком или лежит за симлинком, в список не
попадает; вместо него в журнал уходит предупреждение.

Список категорий пересобирается только при изменении результата сканирования,
режима симуляторов или возраста архивов: SwiftUI спрашивает его десятки раз за
проход отрисовки, а сборка списка стоит фильтра архивов и интерполяции строк на
элемент.

### Раздел «Arcadia»

Таблица из `arc mount --list --json` с колонкой-чекбоксом: имя маунта, статус
(`mounted`/`unmounted`), дата последнего использования, размер store. Основной
маунт `~/arcadia` показывается с замком и без чекбокса. Пока идёт сканирование,
поверх таблицы тот же индикатор «Сканирование…», что и в разделе Xcode.

Дата последнего использования — `modificationDate` папки `<store>/.arc`, с
откатом на сам store. Она отражает реальную работу с веткой, тогда как mtime
корня store не меняется после создания.

Создание маунтов в приложении не поддерживается: это чистильщик.

Действий два.

**«Размонтировать выбранные»** — `arc unmount <path>` для каждого выбранного
смонтированного маунта. Store остаётся на месте. Если `arc` отказал, под
таблицей появляется полоса с предложением повторить с `--force`; предложение
живёт, пока маунт всё ещё смонтирован, и снимается при смене раздела.

Перед любым размонтированием измерение размеров останавливается. Обход внутри
живого FUSE-маунта — ровно то, из-за чего том оказывается busy: приложение не
должно ломать собственное размонтирование, а потом предлагать `--force` для
тома, который читает само.

**«Удалить N маунтов · размер»** — снимает всё, что связано с маунтом:

- если маунт смонтирован, `arc unmount <path>`; ответ «Repository seems to be
  already unmounted» не считается ошибкой, потому что список арк может быть
  устаревшим;
- `arc unmount --forget <path>`; его неудача не прерывает операцию;
- если store всё ещё существует, он удаляется напрямую через `removeItem`, но
  только внутри `<home>/.arc/stores/`; Корзина в этом пути не участвует;
- пустая папка маунта снимается через `rmdir(2)`.

Операция считается неуспешной, только если и `--forget` не сработал, и store
удалить не удалось. Размер store берётся из уже измеренного: деструктивный путь
не обходит гигабайты ради числа, которое UI уже показал.

Обе операции идут по списку целиком: отказ на одном маунте не отменяет
остальные, а все сообщения об ошибках показываются вместе.

Все `arc`-команды запускаются с рабочей директорией `~`.

### Раздел «Журнал»

Живой построчный вывод всех команд и итог. Каждая строка получает собственный
идентификатор: текст строк повторяется, а нумерация по индексу заставляла бы
пересобирать массив на каждую строку. Буфер в памяти ограничен 5000 строк и
подрезается блоками по 1000; полный лог всё равно пишется в файл
`~/Desktop/Xcode Cleanup Logs/cleanup-<дата>.log`.

Автопрокрутка работает, только когда вид уже внизу. Если пользователь
прокрутил вверх, вывод больше не тянет вид за собой, а в углу появляется кнопка
«К последним строкам».

### Подтверждение

Кнопка внизу окна действует только на текущий раздел: на вкладке Xcode она
чистит категории Xcode, на вкладке Arcadia удаляет отмеченные маунты. Она
открывает модальный лист: список пунктов с размерами и суммарный размер.

Если в списке есть `simulators` или `simulatorCaches`, отдельной строкой
сказано, что запущенные симуляторы будут выключены: `Cleaner.run` делает
`simctl shutdown all` до того, как трогать хранилища симуляторов.

Для деструктивных пунктов есть чекбокс-подтверждение, и его текст зависит от
операции, потому что удаление в этих двух потоках означает разное:

- очистка Xcode — «Понимаю, что отмеченные данные уйдут в Корзину и сами не
  вернутся»: `SafeDeleter.trash` кладёт `.xcarchive`, `Xcode.app` и toolchains в
  Корзину, откуда их можно достать;
- удаление маунтов — «Понимаю, что store будут удалены навсегда, мимо Корзины»:
  `removeItem` Корзину не использует.

Без чекбокса кнопка «Удалить» заблокирована. Return принадлежит кнопке
«Отмена», Escape тоже отменяет: лист открывается с готовой деструктивной
кнопкой, и случайный Return не должен ничего удалять. Кодовые фразы из скрипта
не используются.

## Архитектура

Вся логика — в `XcodeCleanerCore`, без SwiftUI и без main actor; UI-таргет
`XcodeCleaner` состоит из `AppModel` и представлений.

- `CleanupKind` (enum): категория. Заголовок, строка последствий, группа,
  порядок выполнения (`executionOrder`).
- `CleanupGroup` (enum): `.safe` / `.attention` — восстановится само или нет.
- `CleanupItem` (struct): конкретный путь или simctl-операция, категория,
  размер (nil, пока не измерен), `isDestructive` и `action`
  (`clearContents` / `trash` / `simulators`).
- `ItemResult` и `CleanupReport` (structs): исход по каждому пункту и итог
  прогона с замерами диска до и после; статуса выполнения на самом
  `CleanupItem` нет.
- `CachePaths` (struct): все пути-источники в одном месте.
- `DiskSpace` (struct): свободно/занято/всего, читается из `URLResourceValues`.
- `Scanner` (Sendable struct): только чтение. Строит `ScanResult` из allowlist
  путей, `xcrun simctl list -j`, `xcrun simctl runtime list -j`,
  `xcode-select -p`, `arc mount --list --json`; размеры считает отдельным
  вызовом `measureSizes(for:onSize:)` не более чем в четыре потока.
- `DirectorySizer` (enum): обход дерева с проверкой `Task.isCancelled` каждые
  256 файлов, чтобы отмена доходила до обхода внутри FUSE-маунта.
- `SafeDeleter` (Sendable struct): единственное место удаления. Путь должен быть
  в allowlist, не быть симлинком и не лежать за ним; содержимое каталога
  удаляется по элементам; элемент на другом `st_dev` пропускается с ошибкой.
  Archives, Xcode.app и toolchains уходят в Корзину через
  `FileManager.trashItem`, кэши удаляются напрямую.
- `Cleaner` (Sendable struct): порядок выполнения, `simctl`, отчёт.
- `ArcMountManager` (Sendable struct без состояния): list/unmount/forget/rmdir(2)
  через `CommandRunner`; размеры store считаются вместе с остальными в
  `Scanner.measureSizes(for:onSize:)`.
- `CommandRunner` (protocol + `ProcessCommandRunner`): запуск `Process`,
  построчный стриминг stdout/stderr в лог через `@Sendable` callback.
- `CleanupLogFile` (final class): файл лога, запись под замком прямо из
  фоновых потоков.
- `RussianPlural` (enum): формы числительных для UI и для подписей, которые
  строит сам core.
- `AppModel` (`@Observable`, `@MainActor`): состояние UI, выбор, диск,
  прогресс, журнал.

Порядок выполнения очистки: проверка, что `Xcode`, `Simulator`, `xcodebuild`,
`xctest` не запущены (`pgrep -x`), иначе остановка с сообщением;
`simctl shutdown all`, если в прогоне есть симуляторы или их кэши; кэши;
`simctl delete unavailable`; `simctl runtime dyld_shared_cache remove --all`;
выбранный режим симуляторов; Archives; Xcode.app; toolchains; проектные кэши;
`sync`; замер диска. Ошибка одного пункта не останавливает прогон.

## Тесты

XCTest, target `XcodeCleanerCoreTests` (UI-таргет тестами не покрыт):

- Парсинг фикстур JSON `simctl list`, `simctl runtime list`, `arc mount --list`.
- `SafeDeleter` и `Cleaner` во временной папке: удаляют содержимое
  allowlist-каталога, не удаляют сам каталог, пропускают симлинки, отказывают
  пути вне allowlist.
- Фильтр Archives по возрасту.
- Выбор «старых» Xcode и toolchains по активному `xcode-select` и `swift-latest`.
- Формат размеров и формы русских числительных.
- `CommandRunner` подменяется фейком; реальные `arc`/`simctl` в тестах не
  вызываются.

Ручная проверка: `./build.sh`, запуск `.app`, скан, удаление одного тестового
unmounted-маунта, сверка «Освободится» с фактическим df.

## Вне scope

Menu bar-режим, автозапуск по расписанию, нотаризация, распространение.
